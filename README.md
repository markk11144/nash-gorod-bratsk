# «Наш Город» — лендинг агентства недвижимости в Братске

Готовый к настройке русскоязычный лендинг на Next.js. Сайт основан на публично проверяемой информации об агентстве и не содержит вымышленных сотрудников, отзывов, наград, комиссий или гарантий.

## Что реализовано

- адаптивный лендинг с локальным позиционированием;
- оригинальная hero-иллюстрация без чужих фотографий;
- подтверждённые контакты, команда, услуги и динамический рейтинг;
- пересказы отзывов со ссылкой на 2ГИС;
- форма консультации в доступном модальном окне;
- форма предварительного ориентира стоимости;
- Telegram, CRM и SMTP-адаптеры заявок;
- российская маска телефона, Zod-валидация, honeypot, защита от быстрых и повторных отправок;
- Метрика только при наличии переменной окружения;
- metadata, Open Graph, Twitter Card, favicon, sitemap, robots и JSON-LD;
- страница проекта политики обработки данных;
- Vitest-тесты основных чистых функций и интеграционных адаптеров.

Исследование находится в [RESEARCH.md](./RESEARCH.md), журнал источников — в [SOURCES.md](./SOURCES.md).

## Требования

- Node.js **20.19.0 или новее**;
- npm, входящий в стандартную установку Node.js.

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

Проверки:

```bash
npm run lint
npm run test
npm run build
npm run start
```

### Примечание о TypeScript 7

TypeScript 7.0.2 перенёс runtime-entry из `lib/` в `dist/`, а Next.js 16.2.10 пока проверяет старый путь. Скрипт `scripts/ensure-typescript-compat.cjs` после установки создаёт минимальный прокси-файл в установленном пакете TypeScript. `npm run build` и `npm run lint` сначала выполняют полноценный `tsc --noEmit`; проверка типов не отключена.

## Переменные окружения

Скопируйте `.env.example` в `.env.local`. Ни одна интеграция не обязательна для локальной разработки.

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен Telegram-бота |
| `TELEGRAM_CHAT_ID` | чат или канал для заявок |
| `CRM_WEBHOOK_URL` | HTTPS webhook CRM |
| `CONTACT_EMAIL` | получатель email-заявок |
| `SMTP_HOST` | SMTP-сервер |
| `SMTP_PORT` | обычно 587 или 465 |
| `SMTP_USER` | логин SMTP, если нужен |
| `SMTP_PASSWORD` | пароль SMTP, если нужен |
| `SMTP_FROM` | подтверждённый адрес отправителя |
| `NEXT_PUBLIC_SITE_URL` | канонический URL, например `https://example.ru` |
| `NEXT_PUBLIC_METRIKA_ID` | цифровой ID Яндекс Метрики |

### Поведение без переменных

- В development заявка маскируется и записывается в серверный лог; форма показывает успех.
- В production без настроенных каналов API возвращает 503, а интерфейс предлагает позвонить. Фальшивый успех не показывается.
- Если настроено несколько каналов, они вызываются параллельно; достаточно успешной доставки хотя бы в один.

## Подключение Telegram

1. Создайте бота через BotFather самостоятельно и не передавайте токен в переписке.
2. Добавьте бота в нужный чат.
3. Укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в Vercel или `.env.local`.
4. Перезапустите приложение и отправьте тестовую заявку.

## Подключение CRM

`CRM_WEBHOOK_URL` получает POST JSON с типом формы, контактом, задачей, параметрами объекта, комментарием и `submissionId`. Webhook должен отвечать HTTP 2xx. Если CRM требует подпись или иной формат, адаптируйте `src/lib/lead-delivery.ts`.

## Подключение email

Укажите `CONTACT_EMAIL`, `SMTP_HOST` и `SMTP_FROM`. Для SMTP с авторизацией добавьте `SMTP_USER` и `SMTP_PASSWORD`. Порт 465 автоматически включает защищённое соединение; для 587 используется STARTTLS, если его поддерживает сервер.

## Аналитика

Без `NEXT_PUBLIC_METRIKA_ID` скрипт Метрики не загружается, а `trackEvent()` является no-op. Реализованы события:

- `hero_cta_click`;
- `phone_click`;
- `whatsapp_click`;
- `telegram_click`;
- `vk_click`;
- `map_click`;
- `reviews_click`;
- `consultation_form_open` / `consultation_form_submit`;
- `valuation_form_open` / `valuation_form_submit`.

Перед подключением аналитики проверьте текст политики и необходимость cookie-уведомления.

## Где менять данные

- Основные контакты, реквизиты, ссылки и рейтинг: `src/data/company.ts`.
- Услуги и сценарии: `src/data/services.ts`.
- Команда: `src/data/team.ts`.
- Пересказы отзывов: `src/data/reviews.ts`.
- FAQ: `src/data/faq.ts`.
- Источники, используемые приложением: `src/data/sources.ts`.

Не дублируйте телефон и ссылки внутри новых компонентов — используйте `company` и helper-функции из `src/lib/contacts.ts`.

## Обновление рейтинга

1. Откройте подтверждённую карточку 2ГИС.
2. Обновите `value`, `ratingCount`, `reviewCount` и `checkedAt` в `src/data/company.ts`.
3. Зафиксируйте дату и новое значение в `RESEARCH.md` и `SOURCES.md`.
4. Повторно выполните тесты и build.

## Замена изображений

`public/images/hero-city.webp` — специально созданная иллюстрация, а не реальная фотография Братска. Она может использоваться до получения официальных материалов.

`public/images/logo-nash-gorod.png` — рабочая копия логотипа из подтверждённого профиля агентства на Домклик. Для финальной публикации желательно заменить её исходным SVG/PNG владельца без изменения пропорций. Базовые цвета интерфейса взяты из опубликованного логотипа: жёлтый `#FEED01`, зелёный `#61B400`, графитовый `#20241F`.

Для фотографий команды:

1. Получите оригинальные файлы и письменное разрешение на публикацию.
2. Оптимизируйте до WebP/AVIF, не менее 900×900 px.
3. Поместите файлы в `public/images/team/`.
4. Добавьте путь в поле `photo` в `src/data/team.ts`. До этого карточка показывает нейтральный пустой фотоблок без инициалов.
5. Укажите автора и право использования в `SOURCES.md`.

Нельзя копировать фото из 2ГИС, Домклик или соцсетей только потому, что они доступны публично.

## Защита формы

В проекте есть:

- скрытое honeypot-поле;
- минимальное время заполнения;
- клиентская блокировка повторного submit;
- дедупликация `submissionId` и телефона;
- лимит попыток с одного IP;
- повторная серверная Zod-валидация;
- таймаут внешних запросов;
- маскирование номера в development-логе.

Дедупликация хранится в памяти процесса. Для нескольких serverless-инстансов в production добавьте внешнее TTL-хранилище, например Redis/Upstash, не меняя публичную схему API.

## Развёртывание на Vercel

1. Загрузите репозиторий в Git-провайдер.
2. Импортируйте проект в Vercel.
3. Добавьте production-переменные окружения.
4. Укажите реальный `NEXT_PUBLIC_SITE_URL`.
5. Выполните deployment и проверьте `/robots.txt`, `/sitemap.xml`, `/privacy` и отправку форм.
6. Обновите домен и карточки компании только после подтверждения владельцем.

## Известные ограничения

- Проект не содержит каталога объектов или CMS.
- Предварительная оценка не является отчётом оценщика.
- `AggregateRating` отражает 2ГИС на указанную дату; поисковая система может не показывать self-serving review rich result.
- Точный результат Lighthouse зависит от production-хостинга и сети; локальные показатели нужно повторить после deployment.
- Политика — проект, а не юридическое заключение.
